COMPLETED — CHART IMAGE INPUT METHODS
===============================================================================

ChartUpload currently supports multiple ways of supplying an image.

Browse / Replace:

- A hidden native file input accepts image files
- A custom Browse button triggers the file picker
- Once a file exists, the control can display Replace instead of Browse

Drag and Drop:

- Each chart upload area acts as a drop target
- Dropped files are validated as image files
- The selected image is assigned to the correct timeframe

Clipboard Paste:

- Chart upload areas are focusable
- The user can click a specific chart slot and press Ctrl+V
- Clipboard image data is assigned to the focused chart slot
- This prevents ambiguity about which timeframe should receive the pasted image

Remove:

- A populated chart can be returned to a null file state
- Existing state/update behavior handles removal without additional chart state

===============================================================================
COMPLETED — IMAGE PREVIEW
===============================================================================

ChartUpload displays a preview of the selected image.

The component uses:

URL.createObjectURL(file)

to create a temporary browser URL that can be used as an image source.

A useEffect watches the file dependency.

When the file changes:

- A new object URL is created
- previewUrl is updated
- React renders the new image

The effect cleanup uses:

URL.revokeObjectURL(objectUrl)

to release the previous temporary browser resource when the file changes or the
component is removed.

The component also displays the selected filename.

===============================================================================
DESIGN DECISION — DYNAMIC CHART SLOTS
===============================================================================

At the end of Session 004, the five permanently rendered chart boxes were
reconsidered.

Decision:

The application should NOT require five static chart upload boxes.

Instead, the Charts interface should allow the user to add only the chart slots
needed for a particular journal session.

Target concept:

Charts

[ + Add Chart ]

Each added chart should contain:

- Timeframe selector
- Browse / Replace
- Drag and drop
- Focused Ctrl+V paste
- Image preview
- Remove

The user should be able to have:

- Zero charts
- One chart
- Several charts
- All standard timeframes

without unused permanent chart boxes occupying the interface.

The existing ChartUpload component remains useful. The primary change will be
how App.tsx creates and manages ChartData records.
